# 共建孵化

共建孵化用于处理“现在还没有完整答案，但值得大家共同整理”的主题。它不是许愿池：每个提案都需要说明为什么值得做、需要哪些证据、谁愿意推进，以及什么状态才算完成。

## 从想法到 Wiki

1. **发起提案**：说明缺失内容、目标读者、拟新增或修改的位置、现有资料和完成标准。
2. **征集意见**：社区补充事实、案例、反例、公开来源和内容边界。
3. **确认采纳**：维护者确认主题适合进入 Wiki，并明确负责人和评审人。
4. **形成任务**：将讨论转为 Issue（议题），记录范围、分工和截止节点。
5. **撰写初稿**：负责人按照对应模块的页面模板整理 Markdown 初稿，并发起 Draft PR（草稿拉取请求）。
6. **评审发布**：检查事实、来源、隐私、版权和排版，合并后在原讨论中回填正式页面链接。

## 状态约定

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 征集中 | 方向值得讨论，正在收集资料和意见 | 补充证据并寻找负责人 |
| 待补证据 | 有观点，但缺少可靠来源或可复核材料 | 查找公开来源、澄清经验边界 |
| 已采纳 | 维护者确认适合进入 Wiki | 建立 Issue 并明确分工 |
| 撰写中 | 已有负责人形成结构或初稿 | 提交 Draft PR |
| 评审中 | 拉取请求已经提交 | 完成事实、隐私和格式评审 |
| 已收录 | 内容已经合并并发布 | 回填页面链接，保留后续反馈 |
| 暂时搁置 | 缺少负责人、资料不足或暂不适合公开 | 补足条件后重新启动 |

## 发起人的责任

发起人是第一责任人，但不是主题的永久所有者。发起人需要定期整理讨论结论、更新进度、说明仍缺少什么，并在内容发布后回填链接。如果连续 30 天没有实质进展，其他成员可以提出接手；维护者确认后可变更负责人。

## 什么主题适合发起

- 某门课程缺少完整的学习路线和实验避坑指南。
- 某项竞赛的资料散落，需要建立可持续更新的训练入口。
- 某类科研工具或实验流程有共性问题，值得形成方法说明。
- 某年度保研政策需要建立带来源和核验时间的索引。

单个错别字、失效链接或明确的小修正可以直接提交拉取请求，不必先发起共建提案。纯个人宣传、没有公开权限的材料和无法核验的传闻不会进入孵化流程。
